## 1. 阶段目标与边界

**一句话**：把「数据放哪、配置从哪读」定死，让 CLI 成为事实入口，并堵掉 `serve` 被依赖的架构口子。

**本阶段不做**（明确）：

- 不做 memory / 角色延续、不做 WebUI 重整与设置页、不做 LLM 提供商重构、不做统一连接路径。
- 不做备份系统、不做打包 / GUI、不做项目标准化 / CI、不做彩蛋、不宣布公开。
- **不承诺旧配置 / 旧数据兼容**：迁移工具与兼容层一律 v1.0+ 再做；旧 `config/`、`.env` 由开发者手动迁移。

### W1 · 统一数据目录（`feat/paths`，1–1.5 天）

**目标**：所有路径只从 `src/aris/paths.py` 出。

**新增 `src/aris/paths.py`**：

```python
# 计划接口（名字可微调，语义不可变）
def data_root() -> Path: ...      # ARIS_DATA_DIR > 开发树 ./data > ~/.project-aris
def config_dir() -> Path: ...     # data_root()/config
def state_dir() -> Path: ...      # data_root()/state（运行时状态，可重建）
def logs_dir() -> Path: ...
def env_file() -> Path: ...       # data_root()/settings.toml / secrets.toml（W2 用）
def characters_dir() -> Path: ...
def skills_dir() -> Path: ...
def models_dir() -> Path: ...
def notes_dir() -> Path: ...
```

- 路径一律**绝对路径**（`resolve()`）。
- 开发树判定：仓库根同时存在 `pyproject.toml` 与 `src/aris`；否则安装模式。
- `ARIS_DATA_DIR` 为空 / 不存在时按上述顺序回落，并记 warning（仅安装模式且无注入时）。
- **`ARIS_DATA_DIR` 只从进程环境读，不从 TOML 读**（否则鸡生蛋：先要知道 data 在哪才能读配置）。

**改动面**（以 grep `data/` 与 `get_settings().data_dir` 为准逐个替换）：

- `src/aris/config.py`：`data_dir` 默认值改由 `paths.data_root()`

- `src/aris/datadir.py`：目录分层改调 `paths`；`REQUIRED_DIRS` / `CARRIED_PATHS` 更新（新增 `state/`）
- `src/aris/serve/steps.py`、`src/aris/store/*`、`src/aris/core/llm/fetch.py`（models.dev 缓存）、`src/aris/behavior/skills/note/tools.py`、`src/aris/mcp/runtime.py`（媒体目录）、`src/aris/webui/routes/config.py`（备份目录）

### W3 · CLI 事实入口 + 模块开关（`feat/modules-cli`，2–3 天，依赖 W1/W2）

**3.0 前置：CLI 拆包（建议同时做）**
`cli.py` 已 1012 行、20 个 `_cmd_*`；再加三组命令会恶化。拆成：

```
src/aris/cli/
  __main__.py      # 入口转发
  parser.py        # argparse 定义
  main.py          # 分发
  commands/        # doctor.py llm.py serve.py chat.py db.py knowledge.py store.py tools.py services.py info.py config.py modules.py
```
保持 `[project.scripts] aris = "aris.cli:main"` 兼容（`cli/__init__.py` 导出 `main`）。**纯搬运，不改行为**，单独一次提交。

**3.1 模块清单 `src/aris/modules.py`**（顶层，不得 import serve）：

```python
@dataclass(frozen=True)
class ModuleSpec:
    name: str                 # "knowledge"
    enabled_key: str          # "modules.knowledge"
    depends_on: tuple[str, ...]
    service_prefix: str       # "knowledge."
```

7 个模块：store / knowledge / mcp / behavior / webui / character / voice。
依赖关系建议：`knowledge → store`、`webui → store + knowledge`（其余无硬依赖）。

**3.2 `data/config/modules.toml`**：全部默认 true；`knowledge.toml` 的 `enabled` 并入并删除。

**3.3 开关语义**：
- 关闭模块 = `serve.assemble()` **不 import** 该模块（注册即 import，必须先读配置再 import）。
- `services` 步骤按清单核验：缺失服务若来自关闭模块 → error 日志 + 标注依赖方 `skipped`，不退出。
- 仍为 `required` 的只有「启用 store 时的 `store.db`」。
- 每个模块的 probe / start 步骤按启用状态裁剪，启动清单可见「已关闭 / 已跳过」。

**3.4 CLI 命令**（只读）：
```bash
aris info
aris config path|list|show <name>|validate|env
aris modules list|status|enable <name>|disable <name>
```
`enable/disable` 只改 `modules.toml` 的布尔值，不碰程序状态；下一次启动生效。

**3.5 测试隔离（顺手还债）**：`ToolRegistry.__init__` 会 `provide("tools.execute")`，测试里新建 registry 会覆盖全局服务；`conftest` 又全局 `assemble()`。新增 `tests/support/bus_snapshot.py`（保存 / 恢复 `_services`、`_subscribers`），或给 `ToolRegistry` 加 `provide_services=False`。模块开关测试必须走它。

**验收**：关闭 knowledge 后 `aris serve --dry-run` 显示 knowledge skipped、webui 记 error 但不退出；`aris modules list` 如实反映；`tests/test_modules.py` 覆盖 7 个开关与依赖冲突。

## 7. 本项目特有的坑

- **测试是宿主**：`tests/conftest.py` 调 `serve.assemble()`；改装配顺序会波及全量测试。
- **注册即 import**：模块服务在 `__init__.py` 的 import 时注册，所以模块开关必须“先读配置，再决定 import”。
- **单槽服务**：`tools.execute` / `loop.run` / `skills.menu` 是全局单槽；测试里新建 `ToolRegistry` 会覆盖（W3 修）。
- **provider 密钥**：`api_key_env` 仍读 `os.environ`，TOML 迁移后必须 `setdefault`，否则 LLM 静默降级为“缺 key”。
- **便携 PG**：路径改动会影响 `pgdata` / `pg` / socket 目录；先跑 `test_store*portability*`。
- **不做兼容**：不要自作主张写旧 `config/` / `.env` 迁移器。
- **推送**：本地工作区只有修改权限；push 可能需要开发者执行或用 `GIT_SSH_COMMAND='ssh -F /dev/null' git push`。
