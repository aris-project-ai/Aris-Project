## 一、记忆的分层（定案）

| 层 | 内容 | 进上下文的方式 | 检索方式 |
|---|---|---|---|
| **一级** | 小会话上下文 + compact 摘要 | 就是当前上下文本身 | —（见第六节） |
| **二级** | **中期记忆**：近期事件（近 **14~15 天**）；**两周记** | 近期事件按 `w_eff` 排、两周记取最近一篇（见第五节） | **emb + SQL**（仅事件有向量） |
| **三级** | **长期记忆**：近 1 年内的**重要事件**（权重筛出来的） | 靠「关键记忆」直接进上下文（见 4.1） | **emb + SQL** |

- **分层的轴是时间**（用户明确纠正：二级三级都是按时间分的，**不是按权重**）；
  权重是**横切所有层**的另一根轴（第四节），它决定"谁排在前面 / 谁能直接进上下文"，
  但**不改变一条记忆属于哪一层**
- **聚合产物只有一种：两周记**（2026-09-29 定）——原设想的"周记 / 月记"两档**取消**：
  二级窗口就是 14~15 天、正好两周，聚合成一篇「两周记」即可，不再分周记与月记
- 「特别记忆」「关键记忆」**不是第四层**，是优先级标记（见 4.1）

## 二、记忆的内容形态（定案）

三类产物，**语义分开**（2026-09-29 按「只做两周记」修订）：

| 产物 | 是什么 | 进上下文 | 向量化 |
|---|---|---|---|
| **事件** | **发生在 Aris 身上/身边的事**（不是对话记录！），**一句话** | 进（关键记忆 + 近期事件，见第五节） | **是**（**唯一**向量化的产物） |
| **对话总结** | 一段对话的**详细总结** | 不进（可回溯，兼**两周记的原料**） | 否 |
| **两周记** | 拿该两周窗口的对话总结（+ compact 摘要）聚合 | 进（取最近 1 篇） | **否** |

> **2026-09-29：总结类产物一律不向量化**（用户定）。理由：周记/两周记讲的是**一整段的
> 连贯叙事**，一旦切块进向量库，检索回来的就是**残缺片段**，模型据此回答会走样。
> 它们靠**时间直取**（最近一篇注入、更早的按时间范围读），不靠相似度。

### 2.1 「事件」的判定标准（2026-09-28 定案）

> 背景：同一句"事件"，不同模型切出来的粒度差得远——有的切得极细（"说了句话"也算）、
> 有的把整段对话总结成一条、有的干脆不切。**所以定义必须不含糊**，且能直接进提示词。

**概念边界**（三种东西别混）：

| 概念 | 是什么 | 粒度 |
|---|---|---|
| **原始消息** | 用户/Aris 的一条消息 | 最细（**不是事件**） |
| **事件** | **一个有意义的行动单元** | 中（本文件的主角） |
| **对话总结** | 一整段对话的详细总结 | 最粗（**不是事件**） |

**切分单位 = 有意义的行动单元**，不按时间点切：
- 「16:13 和 Morin 说了句话」→ 是事件，但**不重要**（太碎，不该抽）
- 「某时间段和 Morin 商讨了下午干什么」→ 是事件，**够格**（有意义的行动）

**"重要吗"只是粒度筛选标准**：值得被记住的才抽，宁少勿滥。

**表达 = 自我叙述，但加约束防偷懒**（用户：不能让它偷懒）：

| 偷懒形态 | 例子 | 约束 |
|---|---|---|
| 空泛无信息 | "和 Morin 聊了天" | 必须含**具体话题/对象**与**结果或结论** |
| 用句式凑数 | "我在 16:13 做了一件事" | 禁止"做了某事"类占位 |
| 一条顶一段 | 整段对话总结成一条 | 与"行动单元"冲突 → 必须**可数**（多件事就多条） |
| 太短 | 三五个字 | 设**字数下限**（如 ≥12 字，具体值实现时定） |

- **句式不定死**（用户明确：不用「我在 xx 时间干了 xx」这种丑句式）
- **时间走参数、叙述用相对时间**（"下午""后来"），绝对时间不进句子

### 2.2 事件挂的参数（定案）

| 参数 | 说明 |
|---|---|
| `occurred_from` / `occurred_to` | **时间段**（不是时间点；用两列而不是 `tstzrange`，便于索引与排序） |
| `weight` | 权重（衰减 / 排序 / 关键记忆判定用，见第四节） |
| `session_id` | **来自哪个小会话**（溯源） |
| `source_ref` | 更细的溯源（哪几条消息 / 哪个大会话） |
| `schema_version` | 抽取所用的定义版本（**换模型时溯源**） |

**只有一个是"内容"，其余都是参数**——用户：「就一（个字段），但可以给它加参数后保存」。

### 2.3 事件抽取回归样例（2026-09-29 定案）

> 用途：① 实现时直接搬进 `tests/` 当用例；② **换模型 / 改提示词时跑一遍，看粒度漂没漂**
> （2.1 那套标准靠模型执行，同一段对话换模型可能切成 5 条也可能切成 1 条）。
> **样例按真实对话写**（用户要求：真实对话没那么简单）——所以刻意带寒暄干扰、工具调用、
> 无结果的协商、情绪类内容。判据：正例的条数与要点对上、反例必须是 0 条。

**样例 1（正例 · 有寒暄干扰、含两件事）**

```
[12:03] Morin: 中午吃啥
[12:04] Aris: 楼下那家面？上次你说还行
[12:05] Morin: 行
[13:40] Morin: 对了，我下周二到周四去上海出差
[13:41] Aris: 那周四回来的高铁几点
[13:42] Morin: 晚上八点多，回来那天想让你帮我盯一下快递
[13:43] Aris: 好，到时候把单号发我
[22:10] Morin: 累了，睡了
```

期望 **2 条**（午饭三段**不抽**：日常琐事、没有值得记住的结果）：
① 「得知 Morin 下周二到周四去上海出差，周四晚上八点多回来」
② 「答应 Morin 在她出差回来那天帮忙盯快递，等她发单号」

**样例 2（正例 · 带工具调用，只抽结论）**

```
[15:02] Morin: 周末想爬山，帮我看看天气
[15:02] Aris:（调 web_search：周末天气）
[15:03] Aris: 周六有中雨，周日转晴
[15:04] Morin: 那算了，改下周吧
```

期望 **1 条**：「因周末有雨，和 Morin 把爬山改到下周」——**中间的查询动作不是事件**，
"改期"这个**结果**才是。

**样例 3（正例 · 状态/关系类，最容易漏）**

```
[21:20] Morin: 最近有点烦，项目压得紧，晚上老睡不着
[21:21] Aris: 是一直这样还是这两周
[21:24] Morin: 这两周吧，等这版发出去应该会好
[22:40] Morin: 跟你聊完舒服多了，谢谢
```

期望 **1 条**：「Morin 提到这两周因项目压力大睡不好，聊过之后说舒服多了」——
**发生在 Aris 身边的状态变化也算事件**，不是只有任务才算（宁少勿滥，取 1 条不取 2 条）。

**样例 4（反例 · 全程寒暄）**

```
[08:10] Morin: 早
[08:11] Aris: 早呀
[12:30] Morin: 吃了吗
[12:31] Aris: 吃了
[23:50] Morin: 晚安
```

期望 **0 条**。

**样例 5（反例 · 有过程无结果 + 太碎）**

```
[16:13] Morin: 在干嘛
[16:13] Aris: 在整理知识库
[16:20] Morin: 哦
[17:05] Morin: 晚上吃啥
[17:06] Aris: 你想吃啥
[17:07] Morin: 都行
[17:40] Morin: 那还是煮面吧
```

期望 **0 条**：整段都在协商、没有结论性结果，「16:13 在整理知识库」太碎。
与样例 2 对照记住一句话：**有结论才抽，过程不抽**。

> 实现时：这 5 条落成用例（需真实 LLM 调用 → 标记为可跳过的集成用例，跑法沿用
> `tests/` 现有约定），人工复核一次输出；`schema_version` 变了就重跑。

## 三、写入时机（定案，含关键的成本理由）

| 时机 | 一次调用产出 | 为什么是这个时机 |
|---|---|---|
| **大会话结束** | **对话总结 + N 个事件**（模型**自主划分**事件边界） | **缓存命中**：大会话一般最多连续几小时，这期间提示缓存断不了；若按"新建小会话"的标准触发，万一隔了几天缓存已过期，**全量新缓存会让成本暴增** |
| **每两周** | **两周记**（拿该窗口的对话总结聚合；2026-09-29 定，取消月记） | 调用少，冷缓存可接受 |
| **模型主动**（工具） | 单条事件 | 允许，但**工具描述里写明别太频繁**，防止滥用 |

- **对话总结与事件在同一次调用里产出**（省一次调用）
- **事件边界由模型自主划分**（一段长对话可能包含多个事件）
- **不需要 `autorun`**：归纳是**事件驱动**（挂在 `D3/D4` 的大会话边界上），
  而非"每晚 12 点"式定时——这正好绕开了已搁置的 autorun
- **两周记的输入** = 该窗口内的「对话总结」+「compact 摘要」（见第六节），按时间序、
  每条带 id 便于溯源；**不做二次聚合**（月记 / 季记一律不做）

## 四、优先级标记与衰减（定案）

### 4.1 两种标记（都是**权重**的特例，横切所有时间层的记忆）

| 标记 | 语义 | 效果 |
|---|---|---|
| **特别记忆** | 模型（或用户）给某条记忆**加权** | **检索结果里排在前面** |
| **关键记忆** | `w_eff` 到阈值（5.0） | **直接进上下文**（不必检索命中） |

- 所以"关键记忆"**不是一级/二级/三级的第四层**，而是**权重足够高后自动获得的待遇**
- **谁可以动**：模型自己可以（工具），**用户也可以手动标**（WebUI，见第八节）

### 4.2 权重与衰减（2026-09-29 定案）

**全整数、位运算（2026-10-01 定，不用浮点）**：

```
w_eff = (weight + hit_count × HIT_GAIN) >> floor(Δt / H)，  Δt = now − last_reinforced_at
```

| 量 | 值（单位="点"） | 说明 |
|---|---|---|
| `weight` | 初始 **100** | 手动/模型「特别记忆」= 直接加大这个值（1 点 = 旧浮点方案的 0.01，够细） |
| `HIT_GAIN` | **100** | 命中一次 = +1（整数加法，永不丢精度） |
| `hit_count` | 0 起 | **唯一会自己涨的量**（见 4.3） |
| `H`（半衰期） | 二级 **14 天** / 三级 **180 天** | 二级对齐"两周"这个窗口；三级对着"近 1 年"量级 |
| 关键阈值 | `w_eff ≥ 500` | = 4 次命中，或一次手动加权 |
| 封顶 | `w_eff ≤ 800` | 防刷分 |
| 消失阈值 | `w_eff < 5` | **不注入、不检索**，但**数据保留**（将来才谈冷库） |

- **衰减 = 每过一个半衰期整体右移一位**（`>>`）：整数、精确、可重复；PG 里就是
  位运算（`(weight + hit_count*100) >> floor(extract(epoch from now()-last_reinforced_at)/(H*86400))`）
- 想更平滑就把 `H` 调小（衰减步长恒为"一个半衰期折半"），不必引入小数
- 负权重 = 软隐藏（4.4），数值上直接判 `< 0`

- **惰性计算，不落库**：衰减只在读时按公式算，**没有定时任务、不改写历史行**
  （`autorun` 已搁置，这是唯一可行的形态）→ 好处是**调参不用洗数据、结果随时可重算**
- **唯一写库的路径是"强化"**（命中写回 `hit_count` 与 `last_reinforced_at`，见 4.3）
- "衰减到消失 → 进冷库"：**冷库暂不做**，v1.0 只是不再注入 / 不再被检索

### 4.3 命中强化与防刷分（2026-09-29 定案）

- **`+1` 只发生在真实检索命中时**（`memory_search` 工具、或兜底主动检索）；
  **注入不算命中**（否则每轮注入会自动刷分）
- **去重粒度 = 一次检索调用**：同一次调用里同一条记忆命中多次，只 `+1`
- 命中即写回：`hit_count += 1`、`last_reinforced_at = now()`
- **上限**：`w_eff` 封顶 **800**；且**靠命中涨到关键阈值（500）之后不再靠命中上涨**
  ——想更高只能手动 / 模型加权（"特别记忆"）

### 4.4 负数权重（定案）

**负数 = 软隐藏**：检索不返回、不进上下文，但**数据保留**，用户能在 WebUI 看到并改回来。
（另有**硬删除**，见第八节：那是真删行。）

### 4.5 检索与权重的合成（定案方向）

**先按相似度排序，再把高权重的"稍微往前提一提"**（不是权重主导排序，是微调位置）。

## 五、注入与调用时机（2026-09-29 定案）

### 5.1 注入三块（不设 token 预算）

| 块 | 取法 | 配额 | 内容规范 |
|---|---|---|---|
| ① **关键记忆** | `w_eff ≥ 500`，**不检索**，直接取 | **≤7 条** | 每条 ≤80 字 |
| ② **近期事件** | `occurred_from` 落在近 **14 天**，按 `w_eff` 排 | ≤10 条 | 每条 ≤60 字 |
| ③ **两周记** | 最近 **1** 篇 | ≤1 篇 | ≤1200 字 |

- **不设 token 预算**（2026-09-29 用户定）：窗口大小是 **compact** 的事，
  记忆注入只管**条数与内容规范**——不再算"占窗口百分之几"
- 更早的两周记**不注入**，但可**按时间直取**（WebUI `/memory` 页 + 给 Aris 一个
  按时间范围取的工具，见 5.4），全程**不碰向量**

### 5.2 放在哪、何时取、失败怎么办

- **system prompt 保持静态**（只有 persona + 工具提示），**记忆块每轮临时拼在「历史尾部」**、
  **不写进 `history`**；精确位置（2026-10-01 定）：**常驻三块放末条 user 之前**，
  **12h 兜底的检索结果放末条 user 之后**——两者别混
  - 理由（D15 那条）：system 一动，整个提示缓存的**前缀全失效**；放在尾部则前缀照命，
    只失效最后这一小段
- **每轮对话前组装**，取数走总线服务（建议名 `memory.inject_context`）
- **失败降级**：DB 没起 / 表不存在 / 取数异常 → **记日志 + 跳过注入继续聊**
  （optional 级，与现有失败分级一致，绝不因为记忆问题阻断对话）

### 5.3 调用时机：默认自主检索 + 兜底主动检索（2026-09-29 定案）

- **默认 = Aris 自主搜索**：给一个 `memory_search` 工具（与 `knowledge_search` /
  `web_search` 同一风格：**自主调用，不做每轮自动注入**），4.3 的 `+1` 就发生在它上面
- **兜底主动检索**：距上次记忆检索超过 `fallback_after_hours`（**默认 12 小时**）时，
  在**接下来这一轮**由系统主动用**用户的原问题**做一次检索，把结果**插在询问之后**
  （用户消息之后、发请求之前），同样**不写进 `history`**
  - 立意：Aris 可能"忘记用记忆"，兜底保证它至少隔一段时间就真的看一眼记忆
  - 兜底这一次**算真实检索 → 计 hit**（去重规则同 4.3）

### 5.4 按时间取历史产物（2026-09-29 定案）

- 两周记 / 对话总结**不向量化**，所以给它们的入口是**时间**而不是相似度：
  WebUI `/memory` 按时间浏览；给 Aris 的工具也按时间范围取（如"上个月的两周记"）

## 六、compact 与记忆的关系（2026-09-29 定案）

| 环节 | 定案 |
|---|---|
| **compact 的输入** | **只有真实对话历史**——`system prompt` 与**注入的记忆块都不参与压缩** |
| **compact 的产物** | 一段摘要；**落库为 `kind=compact`**（不向量化；查询时按 `kind` 与对话总结分开取） |
| **compact 后重组** | `system prompt` + **记忆块** + 〔**摘要** + **compact 前最后 3 条原文**〕+ 后续新消息 |
| **为什么带尾部原文** | 让对话**顺下来**（衔接语感、接上没说完的话题）；条数进配置，默认 **3** |
| **顺序** | **摘要在前、尾部原文紧随其后**（这样时间顺序才是顺的；用户说的"compaction 内容前带上最后几条对话"按此落地） |
| **不重复提炼** | compact 已覆盖的段落，大会话结束时**不再总结一次**（同一段对话只提炼一次） |

- 所以 **compact 不改变**"记忆注入"这套机制：压缩完只是把 system 与记忆块**重新拼回去**
- **compact 触发与预算**（字符估算 × `context_length` 比例）见 `discuss-2026-09-28.md` D5

## 七、表结构（2026-09-29 定案）

**二级三级同表**（用户定："反正二三级是按时间分的"）；表里的 `cid` = **角色 id**
（character id，创建角色时生成，改名 / 改人设都不影响；目录 `data/personas/<cid>/`）：

```sql
memory_entries (
    entry_id           uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
    cid                text        NOT NULL,           -- D1：记忆按角色分区（cid 创建时生成）
    tier               smallint    NOT NULL,           -- 2=中期 / 3=长期（按时间分，不是权重）
    kind               text        NOT NULL,           -- event | summary | compact | digest(两周记)
    content            text        NOT NULL,
    occurred_from      timestamptz NOT NULL,           -- 事件是「时间段」→ 两列
    occurred_to        timestamptz,
    weight             real        NOT NULL DEFAULT 1.0,
    hit_count          integer     NOT NULL DEFAULT 0,
    last_reinforced_at timestamptz NOT NULL DEFAULT now(),
    embedding          vector(384),                    -- 可空！只有 event 有
    session_id         uuid,                           -- 来源小会话（溯源）
    source_ref         jsonb       NOT NULL DEFAULT '{}'::jsonb,
    schema_version     text        NOT NULL,
    meta               jsonb       NOT NULL DEFAULT '{}'::jsonb,
    created_at         timestamptz NOT NULL DEFAULT now(),
    deleted_at         timestamptz                     -- 软删（沿用 knowledge 两表风格）
)
```

- 索引：`(persona_id, tier, kind, occurred_from DESC)`（注入与列举）、
  `WHERE deleted_at IS NULL`（活跃）、HNSW on `embedding` **且只对非空行建**
  （`WHERE embedding IS NOT NULL`——只有事件进图）
- 迁移：owner = `memory`，走 `store/migrate.py` 的 `Migration(owner, version, ...)`
- **软隐藏 vs 硬删除**：
  - 软隐藏 = `weight < 0`（数据留、可改回）
  - **硬删除 = 真 `DELETE`**（WebUI 二次确认）；**只删提炼物**，
    `memory_sessions` / `memory_messages` 的**原文不动**（D5 定案的全量保留原料）
- 会话 / 消息 / 大会话三表（`memory_sessions` / `memory_messages` /
  `memory_conversations`）按 D2/D3 另建，本文不重复
