## 1. 提供商与 LLM 协议更新与优化

- 现状：`core/llm` 已有多提供方抽象 + fallback + 双传输（openai SDK / httpx 手写）+
  流式 + 原生 tool_calls；`providers.toml` 管理模型元数据，`aris llm fetch` 做 /models 同步。
- 目标：跟上上游协议变化（新 API 形态、新字段、新提供方），并优化现有链路
  （重试/超时预算、流式分片拼装、token 统计、错误信息质量）。
- 参考：`developDoc/LLM-PROVIDER-MGMT.md`、`developDoc/API-CALL.md`。
- **商讨结论（2026-09-28，D8/D9）**：
  - **支持 Responses API**（DeepSeek 已正式支持，`POST /responses`、无 `/v1`、无状态、
    无 `[DONE]`；落地要点见 `API-CALL.md` 6.1）
  - **多模态**：模型列表补标模态；图片/文件打通底层；**TUI 与前端不动**
  - **思考模式**：要做，**默认关闭放配置文件**；开启时用 `effort`
  - **不接 Anthropic 兼容端点**
  - **降级与成本纪律**：模型级 `free` 标签 + 自动识别开关（默认关）→ 同一模型 id
    内**免费优先**，免费试完再走 `fallback_models` 链；示例配置去掉默认降级值、
    `race_fallback` 默认 `false`、关掉 SDK 内建重试
- **仍未定**：其余厂商 API 能力面（Moonshot / 通义 / 智谱 / Gemini 兼容等）、

- 目标：技能落到运行时目录 `data/skills/`（不进 git、可随时热改）。

## 4. 多人格与多人格共同运行

- 现状：`persona/` 只有一个 `persona.system_prompt` 服务，提示词工程起步版，
  单人格全局唯一；人设是硬编码文本常量。
- 目标：人格可定义、可选择、可持久化；**多个人格同时运行**（各自会话状态、
  各自上下文），并明确人格之间共享什么。
- 参考：`AGENTS.md`「已定案」的人格相关条目。
- **商讨结论（2026-09-28，D1）**：
  - **语义澄清：「多人格」= 多个人，不是一个人有多个人格**（各自会话、各自记忆，
    互相是不同的人）
  - **载体 = 文件** `data/personas/<id>/`；PG 只存 id 绑定
  - **运行形态 = 单进程多会话**（每会话一个 `persona_id`，总线不改多实例）
  - **记忆按 `persona_id` 分区**（记忆表第一版就带该列，不后补）
- **仍未定**：人格文件的字段结构（世界观 / 人际关系 / 成长轨迹怎么表达）、
  人格之间共享边界的细化

## 5. 上下文压缩（属记忆系统）

- 现状：无压缩，长对话直接顶上下文上限（`providers.toml` 的 `context_length`
  只作元数据，未参与决策）；历史纯内存 + 明文 log。
- 目标：滚动摘要 + 关键信息抽取入记忆，长会话不丢要点、不爆上下文。
- 参考：`AGENTS.md`「待定」节的记忆架构条目。
- **商讨结论（2026-09-28，D2–D5）**：
  - **会话模型**：小会话是**先天属性**（一次 LLM 调用的上下文）不需切；
    **大会话 = 纯时间聚类**，与 session 正交（派生分组，可物化可重算）
  - **分组算法**：k=2 的 1D k-means 组间离差平方和最大 ⇒ 取最大间隔切分；
    数据点 = **消息时间戳**；递归切到"足够连续"为止（不切太细）
  - **compact = 同一会话继续**（`session_id` 不变，成本考虑），旧消息被摘要替换；
    原文全量保留 + 标记可归档
  - **触发判定**：字符数估算 token × `context_length` 比例（比例进配置），
    真实 token 统计落地后切过去
  - `/new` 保留（手动新开 session，TUI 调试用）
- **仍未定**：历史消息检索工具（recall）——"一会再说"；
  ~~大会话结束是否写长期记忆~~ → **已由 D16 定案（写入单元 = 大会话结束）**，
  细节见 `developDoc/MEMORY.md` 三 / 五

## 7. 自动任务与基于自动任务的主动操作

- 现状：一切由用户输入驱动，无调度器、无后台触发，Aris 不会自己发起动作；
  事件总线（`core.bus.emit/subscribe`）**零真实使用者**。
- 目标：定时任务 + 事件触发，Aris 可**主动**做事。
- **商讨结论（2026-09-28，D11）**：
  - 新建独立模块 **`src/aris/autorun/`**，可单独开关
  - **职责 = 纯调度器 + 触发源抽象**（autorun **不自己做任务内容**：写日志归 logging、
    发通知归 notify、记记忆归 memory）
  - 其他模块的核心任务**由各模块自己负责**；**通用列表**（默认不开的）放可读写文件，
    定位像 skill 一样是外围；另有「特殊列表」待商讨
  - **归属切两半**：机制参数 → `config/autorun.toml`；**任务实例 → `data/autorun/tasks.toml`**
    （与 `data/skills/` 同类，不进 git，用读-改-写 + 校验）
  - **模块级 `enabled` + 宽容降级**（依赖缺失记日志降级继续，不阻断启动）
  - 主动操作**允许调任意工具**
  - **v1.0 范围**：~~最小闭环 + WebUI `/autorun` 管理页~~ → **2026-09-28 追加决定：
    暂不实现，v1.0 也不做**（只留设计文档，不写代码）
  - **触发源**：不做（定时/事件/手动三种都留到之后）
  - **目标/计划状态层先不做**，保留为"autorun 的升级路径"，**以后要再商讨**
- **仍未定**：触发源实现次序（定时/事件/手动）、任务的调用方式、
  「特殊列表」的语义、失败兜底与频率上限
