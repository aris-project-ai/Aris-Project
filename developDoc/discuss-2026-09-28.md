### D1 多人格语义（2026-09-28）

**「多人格」= 多个人，不是一个人有多个人格。** 多个人格**同时运行**（当前不启用，但设计
必须支持）：各自独立会话、各自独立记忆，互相是不同的人。

- **人格载体 = 文件**：`data/personas/<id>/`；PG 只存 id 绑定（如会话行上的 `persona_id`）
- **运行形态 = 单进程多会话**：每会话持一个 `persona_id`，总线不改多实例（仍单槽服务名，
  差异靠参数传递）
- **记忆按 `persona_id` 分区**：记忆表从第一版就带 `persona_id`，不后补

### D2 会话模型（2026-09-28，修正 `WEBUI.md:285` 的既有定案）

**小会话是先天属性，不需要我们"切"。** 它就是一次 LLM 调用的上下文窗口本身
（system + 消息序列）；我们只**存储**与**使用**它。

- **小会话**：`session_id` 标识；`/new` 手动开一个新的（TUI 调试用）；上下文接近模型上限时
  **compact** —— **compact 后同一会话继续**（`session_id` 不变），旧消息被摘要替换、继续聊。
  **成本考虑**：不新开会话（新开会话 = 提示缓存前缀全失效 + 摘要重复搬运）
- **大会话**：**纯时间聚类**，与 session 完全正交（可横跨多个小会话，也可能切开一个小会话）
  → 是**从消息时间线算出的派生分组**，不是容器；物化存储便于 WebUI 时间线与记忆整理触发，
  算法改进时可随时重算
- **分工一句话**：小会话按上下文（先天），大会话按时间（派生）

### D3 大会话分组算法（2026-09-28）

用户指定的数学判据：**k=2 的 1D k-means 组间离差平方和最大**

$$d^2_{12} = m(\bar{x}_1-\bar{x})^2 + (n-m)(\bar{x}_2-\bar{x})^2$$

等价的工程形式（区间内 $d^2 = \frac{m(n-m)}{n}(\bar{x}_2-\bar{x}_1)^2$ 单调不减）：

$$d^2_{12} = \frac{m(n-m)}{n}(\bar{x}_2-\bar{x}_1)^2,\qquad
\text{max over } m \;\Longleftrightarrow\; \text{取最大间隔处切分}$$

- **数据点 = 消息时间戳**（用户指定：小会话可能停好几天，消息时间戳不变）
- **递归**：整段取一次最优切点 → 子段继续切；但**不需要切太细**——"大会话只需连续"，
  连续聊几个小时都算同一个大会话 → 停止条件取"子段内部最大间隔相对不显著"（宽松）
- **参数**：切点无需固定时间阈值；停止判定用「子段最大间隔 / 子段中位间隔」的倍数（宽松，如
  3~5 倍）作兜底，配置化

### D4 一个大会话 = 一段连续时间（2026-09-28）

- 大会话的边界是**时间断点**，与"是否换了会话/压缩过"无关
- 记忆整理的触发单元是**大会话**（"这段聊完了"），而非小会话

### D8 提供商与 LLM 协议（#1）—— 2026-09-28 定能力面

### D9 提供商降级与成本纪律（#1 续）—— 2026-09-28

**先纠正一处事实**：现有 engine 的降级**不是换模型**，而是**同一模型 id 换提供方**
（`ProviderConfig.candidates_for()`：多家提供方提供同一模型 id 时按顺序跨家切换——
典型场景是"官方付费 API 挂了切到同模型的免费镜像"）。真正会换模型的是
`fallback_models` 链，而它**已是显式配置项**（`config.py:56`，默认空列表）。

**定案的机制设计**：

1. **模型级免费标签**：`Model.free = true`（**打模型上，不打提供方上**）
   - 理由：同一家可能既有免费又有付费（用户举例 opencode，且其免费额度已收紧、
     非自家头不让用）；将来插件系统还要支持 opencode
2. **自动识别开关（默认关闭）**：若检测到**提供方返回的模型 id**（注意不是我们的统一
   `id`，而是 `request_name` 那一侧）含 `free` 字样，就自动给该模型打免费标签
3. **降级顺序**（同一模型 id 内）：**先试免费提供方 → 免费试完 → 再走 `fallback_models` 链**
   - 顺带副作用（**用户明确认可这是特性**）：因为免费优先按"同一模型 id"聚合，
     所以用户可以把不同真实模型标成同一模型 id，从而实现**自定义分组与自定义降级**
     ——机制上我们只提供"免费优先 + 同 id 分组"，怎么玩是用户的事
4. **fallback 粒度保持现状**：模型级 `fallback_models`（每个模型自己一条链），
   跨提供方同模型仍由 `default_provider_order` 管；不做顶层全局链
5. **默认值纪律（三条一起改）**：
   - 示例配置删掉 `fallback_models = ["deepseek-v3"]` 这类默认值（不再提供"默认链建议"）
   - `race_fallback` 默认改为 `false`（竞速可能双倍计费）
   - **关掉 SDK 内建重试**，只留 engine 的 `retry_count`（默认 1），消除双层重试烧钱
6. **重试保留、竞速默认关**：同模型重试不算乱花钱，保留

- **视觉三挡开关** `vision_transcribe = none | auto | force`：

  - `force` = 所有图片都先转述

- **兜底策略可配**：`transcribe`（转述）/ `reject`（直接拒绝）/ 其余候选
  - **换模型不在候选中**（用户明确：不能换模型——旧 fallback 是为免费模型设计的，
    链上出现付费模型就会静默烧钱）

### D15 单一会话原则（v1.0 硬目标）—— 2026-09-28

- **复用最新小会话**（不按通道开新会话）；**冷却上限 3~5 天**（默认 5 天），

  小会话可跨天存在

- **autorun 分两类**（**autorun 本身已决定暂不做，见 D11**）：主动任务类进当前上下文 +
  带系统提示标识；内部维护类走系统场合

- **场合与去向模型**（只写文档、暂不实现）：场合 = 通道 + 对话方（对话可能一对多）、
  去向 = 输出级枚举（当前场合 / sns / tts / 独白 / 不发）、独白进历史、
