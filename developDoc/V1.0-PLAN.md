| # | 验收项 | 判定方式 |

## 1. 施工纪律（四条铁律）

1. **顺序不可倒**：地基（可迁移性）→ 组装根（serve 上收）→ 人格载体 → 会话落库 →
   data/skills → 记忆数据层 → 聚类/compact → 记忆语义 → WebUI → 附带 → 发布。
   理由见各阶段的「为什么是这个位置」。
2. **`provide` 只许发生在 `serve.assemble()`**：现在 `skills.menu` 是会话构造时注册的全局单槽
   （`src/aris/behavior/skills/manager.py:59`，由 `src/aris/chat/session.py:135` 每会话 new），
   单进程多会话下**后开的会话会覆盖前面的**。M1 必须先修掉。
3. **`system prompt` 全程静态、可变量只从尾部进**：persona + 工具提示 + skills 菜单在构造期
   拼一次（`src/aris/chat/session.py:136-142`）；记忆注入块拼在**末条 user 之后**、
   **不入库、不回灌**。守护的是提示缓存前缀（D15 的成本理由）。
4. **迁移只加不改名**：`src/aris/store/migrate.py:118` 的 drift 检查对已应用迁移**改名即报错**，
   owner=`memory` 的版本号与名字一次定死。每阶段结束必须"能跑 + 有测试"，不留半成品。

## 3. 各阶段详情

### M0 可迁移性与启动幂等（D14）

**为什么最先**：PG 角色名必须在**建任何新表之前**定死。否则 memory 三表建在 `$USER` 角色下，
将来再统一角色名，`pgdata` 属主问题会回头咬（就变成一次数据迁移）。

- **改动面**
  - `store/`：便携 PG 二进制**实际可运行**验证（不只是文件存在）→ 不兼容则 `bootstrap_env()`
    重获取；角色统一为与主机无关的名字（`initdb -U aris`，旧实例探测对齐）；端口被占 → 探可用
    端口、DSN 只在运行期拼（**不入库**）
  - `data/`：补 `personas/`、`skills/`、`autorun/`，启动幂等创建
  - `aris doctor`：加「迁移自检」项 —— `data/` 分层完整性 + PG 可运行性
- **交付**：可迁移自检清单；换机操作说明（README 或 `SERVE.md`）
- **验证**：拷 `data/` 到临时目录跑；故意占住 55432 端口跑一次；角色名不同场景跑一次
- **风险**：旧 `pgdata` 属主不同**不能自动修** → 只报"可操作错误"（写清 `chown` 或重建步骤）

### M5 记忆数据层（D16 §七）

- **改动面**（顺序即验证顺序）
  1. `memory/conf.py` + `config/memory.toml` —— **扁平键**（`cfgtoml` 不支持嵌套表，
     `src/aris/cfgtoml.py:29`）：`halflife_tier2=14` / `halflife_tier3=180` / 关键阈值 5.0 /
     封顶 8.0 / 消失阈值 0.05 / 注入条数与字数 / 14 天窗口 / 兜底 12h
  2. `memory/migrations.py` 建 `memory_entries` + 复合索引 `(persona_id, tier, kind, occurred_from DESC)`
     + 活跃索引（**HNSW 先不建**，先导数据后建索引）
  3. 给 `store.vector.ensure_index`（`src/aris/store/vector.py:98`）**加 `where` 参数**（现在没有）
     → 建 partial HNSW `WHERE embedding IS NOT NULL`（只有事件有向量）
  4. `memory/service.py` 最小闭环：写一条 event → 取候选 → 算 `w_eff` 重排 → 写回命中
- **两条硬约束（勘察实测）**
  - **`w_eff` 不能进 SQL 的 ORDER BY / 表达式索引**（含 `now()`，stable 非 immutable，会退化成顺序扫描）
    → 两段式：先用等值/范围列压候选，向量路取 ANN `top-k × 3~5`，再在 Python 里算 `w_eff` 重排
  - **命中写回必须独立事务**：`store.vector.search` 自建连接、用完即关且**未提交**
    （`src/aris/store/__init__.py:91`），混进 UPDATE 会连带回滚、还会搅乱 `SET LOCAL hnsw.ef_search`
    → 检索完用另一连接批量 `UPDATE ... WHERE entry_id = ANY(...)`，Python 侧去重，失败只记日志
- **其他坑**：`store.vector.search` 的 `select` 默认 `*`（`vector.py:213`）→ 检索**必须显式列**；
  `upsert` 冲突键默认 `id`（`vector.py:139`）→ 传 `conflict_key="entry_id"`；
  `kind` 分流一律显式条件（**不能拿 `embedding IS NOT NULL` 反推**），建议 CHECK 约束或 StrEnum 收口
- **验证**：`uv run aris db migrate` 后 `\d memory_entries`；衰减公式单测；命中写回去重幂等；
  测试显式传 `migrations=` 隔离（别污染全局登记表）

### M6 聚类 + compact（D3/D4/D5 + D16 §六）

- **聚类**：`memory/grouping.py` 纯函数（k=2 的 1D k-means ⇒ 取最大间隔切分 + 递归 + 停止条件
  「子段最大间隔 / 中位间隔 ≥ 3~5」）；物化进 `memory_conversations`，**重算幂等**、
  增量重算 + `recomputed_at`；**不引调度器**（autorun 已搁置）
- **compact**：插入点是 `src/aris/chat/session.py:214` 组装 `list(self.history)` 处
  （session 是唯一持有持久语义的层，**loop/engine/formatters 无状态、不该承担**）；
  触发 = 字符估算 token × `context_length` 比例 —— ⚠️ **`context_length` 目前不参与任何决策**
  （只在展示链路里），要先从 `LLMProvider.get_model` 接线；
  同 `session_id` 把旧消息打 `archived_at` + 写 `kind=compact` 摘要；
  重组 = `system + 记忆块 +〔摘要 + 前 3 条原文〕`；摘要调用失败 → 不压缩继续（记日志）
- **验证**：聚类单测（等间隔 / 单条 / 巨间隔 / 跨天）；`tests/support/mock_llm_server.py` 脚本化摘要，
  断言 `session_id` 不变、`archived_at` 生效、**请求 messages 前缀不变**（只有尾部变）

## 6. 风险表

| 风险 | 对策 |
|---|---|
| 注入破坏 KV cache 前缀 | system 静态 + 只从尾部追加（M1/M3/M6/M7 都守） |
| 单进程多会话串号 | `provide` 只在 assemble；`persona_id` 必填无默认；先修 `skills.menu` 隐患 |
| 换机后 PG 属主/端口不通 | M0 先做且最先定角色名；doctor 给可操作错误 |
| 事件抽取换模型漂移 | `schema_version` + 5 条回归样例，改模型必跑 |
| DeepSeek 400（丢 reasoning_content） | 跨轮恢复 assistant 消息时带全字段 |
| 抽取/两周记成本 | 挂大会话边界（缓存还热）+ 两周一次；工具描述限制频率 |
| 迁移不可回滚 | 只加新表/新列、名字一次定死 |
| 硬删除误删 | 服务端二次确认 + 只删提炼物 + 目标校验 |
| 时间（国庆前后） | M0–M4 先打通"能聊且不丢"，M5–M7 是 v1.0 成色；真紧只裁 M9 附带能力 |
